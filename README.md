# oci-platform

OCI Always Free の上に作る、個人サービス用の共通基盤（方式③）。Cloudflare → Flexible LB → Docker ホスト → MySQL HeatWave の3層と、メールなど VM 単体のサービスの置き場を持つ。

- なぜこの構成か：[方式検討：OCI](https://github.com/alphajinsei/cf-infra-playbook/blob/main/docs/design/oci.md)
- 作る手順と進み具合：[学習ロードマップ：OCI](https://github.com/alphajinsei/cf-infra-playbook/blob/main/docs/roadmaps/oci.md)

アプリが受け取るもの・守ること（共通基盤の仕様）は、Step 9 でここに書く。

### ポートの台帳

app VM の上で、アプリのコンテナが使うポート（VM の側）。LB の NSG は 8000〜8099 をまとめて開けている。アプリを足すときは、ここに1行足してから使う。

| ポート | 使うもの |
| --- | --- |
| 8000 | 共通基盤の既定のページ（`ansible/roles/default_site`） |
| 8001 | [sample-oci-vm-docker](https://github.com/alphajinsei/sample-oci-vm-docker) |

## 構成

```
bin/bastion-proxy     ssh ProxyCommand: reuse or create a Bastion session, then connect through it
ssh_config            generated by Terraform; Include it from ~/.ssh/config (not in git)
ansible/              inside of VMs: site.yml (settings), upgrade.yml (manual upgrade + reboot); roles/mail = Postfix, Dovecot, certbot
terraform/
├── versions.tf       providers, backend (state in Object Storage: tfstate/oci-platform/terraform.tfstate)
├── variables.tf      inputs
├── terraform.tfvars  compartment OCID, region (identifiers, not secrets)
├── network.tf        VCN 10.0.0.0/16, 5 subnets, Internet / NAT / Service gateways, route tables
├── nsg.tf            nsg-lb / app / mail / ops / db and their rules
├── compute.tf        VMs (app, mail, ops), Bastion, ssh_config
├── database.tf       MySQL HeatWave and the policy for its resource principal
├── vault.tf          Vault, key, secrets, dynamic group and policy for VMs
├── mail.tf           mail passwords (Vault), Email Delivery (domain, DKIM, return path, senders), relay IAM user + SMTP credential
├── lb.tf             Flexible LB, Origin CA cert (read from .secrets), default listener (443)
├── monitoring.tf     2 alarms (app down, VM down) -> email, LB access / error logs
├── cloudflare.tf     the only file touching Cloudflare: DNS records (check hostname, mail A and MX)
├── outputs.tf        IDs for later steps and for apps (terraform_remote_state)
└── tf.sh             loads the Cloudflare API token, then runs terraform
```

| サブネット | CIDR | 置くもの | VM（ssh の名前、IP） |
| --- | --- | --- | --- |
| public-lb | 10.0.0.0/24 | Flexible LB | |
| public-dmz | 10.0.1.0/24 | mail | `oci-mail`、10.0.1.10（A1 1 OCPU / 4GB。メールのデータは `/srv/mail`） |
| private-app | 10.0.10.0/24 | Docker ホスト、Bastion の窓口 | `oci-app`、10.0.10.10（A1 1 OCPU / 8GB） |

| private-ops | 10.0.30.0/24 | 作業用 兼 バッチ | `oci-ops`、10.0.30.10（マイクロ、swap 2GB） |

## 使い方

認証は `~/.oci/config` の DEFAULT プロファイル（API キーは `~/claude-sandbox/infra/.secrets/oci/`）。

```bash
cd terraform && ./tf.sh init && ./tf.sh apply         # OCI のリソースと Cloudflare の DNS レコード
ssh oci-app                                            # Bastion 経由（初回はセッション作成で1分ほど待つ）
cd ../ansible && ansible-playbook site.yml             # VM の中
```

- OS は Ubuntu 24.04。セキュリティの更新は毎日自動で入るが、再起動と Docker 本体の更新はしない（コンテナを止めないため）。月に1回などで `ansible-playbook upgrade.yml` を流す（全部更新し、再起動が要る VM だけ1台ずつ再起動する）。
- `tf.sh` は Cloudflare の API トークン（`~/claude-sandbox/infra/.secrets/terraform-oci-dns.env`。権限は Zone Read と DNS Edit だけ）を読み込んでから terraform を実行する。OCI の認証は `~/.oci/config`。
- Cloudflare で Terraform が触るのは DNS レコードだけ（`cloudflare.tf`）。暗号化モード（Full (strict)）、Always Use HTTPS、Origin 証明書は手で設定する。Origin 証明書（15年）はダッシュボードで発行し、`~/claude-sandbox/infra/.secrets/oci-platform-origin.pem` と `.key` に置く。
- LB の既定の行き先は app の 8000 番（`ansible/roles/default_site` の小さなページ）。アプリのポートは 8001 から台帳で割り当てる。確認用のホスト名は `oci-platform.alphajinsei.com`。
- app と ops には oci CLI と `platform-secret <名前>`（共通基盤の Vault からシークレットを取り出す。VM 自身の権限で読むので鍵は要らない）が入っている。アプリは `/opt/apps/<名前>/` に置く（持ち主は ubuntu）。
- 監視はアラーム2つだけ（`monitoring.tf`）：アプリが止まった（LB のバックエンド・セットに異常なバックエンドが3分続く）と、VM が止まった（CPU のメトリクスが10分届かない）。通知は `terraform.tfvars` の `alert_email` へ。アプリを足しても、アラームは足さなくてよい。新しいアプリを apply してからデプロイするまでの間も鳴る。
- ログ：コンテナのログは app で `cd /opt/apps/<名前> && docker compose logs -f app`。LB のアクセスログとエラーログは OCI Logging のロググループ `platform`（`lb-access`、`lb-error`。30日）。
- メール：`alphajinsei.com` の MX は `mail.alphajinsei.com`（mail VM。プロキシなし）。Postfix が受けて Dovecot（LMTP）が `/srv/mail/<ドメイン>/<ユーザー>/Maildir/` に保存し、メールソフトは IMAP（993番）で読む。証明書は Let's Encrypt（HTTP-01、certbot が自動更新）。ユーザーと別名は `ansible/group_vars/mail.yml`（ユーザーは `terraform/mail.tf` にも書く。パスワードは Vault の `mail-<ユーザー>-password`）。設計は [方式検討：OCI のメール基盤](https://github.com/alphajinsei/cf-infra-playbook/blob/main/docs/design/oci-mail.md)。
- SSH の鍵は2つ。VM へのログインは `~/.ssh/oci-platform`（ed25519）。Bastion のセッションは RSA の鍵しか受け付けないので、`~/.ssh/oci-platform-bastion`（RSA）を別に使う（`bin/bastion-proxy` が使う）。
- `~/.ssh/config` の先頭に `Include ~/claude-sandbox/oci-platform/ssh_config` を書いておく。

- NAT Gateway が課金されていたら、`terraform.tfvars` に `use_nat_gateway = false` を足して apply する（app と ops が公開サブネットになり、Internet GW から外に出る。サブネットは作り直しになる）。
